# Airframe 3b · Android emitter (Kotlin/Compose + optional Material 3 scheme) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `airframe build` emits, for a platform with `emit: [kotlin]`, a shared Compose `DesignTokens.kt` and one `DesignColorValues.kt` per fanned-out app, optionally with Material 3 `ColorScheme`s. `build --check` / `emitted-stale` covers them like every other output.

**Architecture:** The `kotlin` emitter sits on the native plan that 3a shipped (`internal/emit/native.go`: `PlanNative`, `Outputs`, `Varies`, `Value`, `FixedWarnings`) and on the naming helpers (`naming.go`). Android has no asset catalog, so colours become data. There are two files:
- **Shared file.** It declares the `DesignTokens` class (runtime-axis enums, non-colour members, colour accessors) and a `DesignColors` data class, with one `Color` field per colour slot.
- **Per-app file.** Each app gets one `DesignColorValues` object holding a `DesignColors` for each appearance, and optionally a Material 3 scheme for each appearance.

**Model:** the 3a emitters `internal/emit/swift.go` and `colorsets.go`, for structure, axis handling, identifier rules, goldens and the typecheck test. Starboard for conventions.

**Tech Stack:** Go 1.27 (`toolchain go1.27.4`), pinned deps only. The Kotlin output targets Kotlin 2.x and Jetpack Compose (`androidx.compose.ui`, `androidx.compose.animation.core`, `androidx.compose.material3`).

**Spec:** `docs/specs/2026-11-27-airframe-design.md` §6.2 (the `android` platform, `naming`, per-token `names`) and §6.7 item 3.

## Global Constraints

- License header on every Go file: `// SPDX-License-Identifier: AGPL-3.0-only`, then `// Copyright 2026 C65 LLC`.
- Deterministic, byte-stable output: LF, final newline, no timestamps; never range a map without sorting its keys.
- Fail closed: anything a platform cannot express is a diagnostic that names it. Never drop it silently, never guess.
- The generated-file header: `// GENERATED by airframe from <content>/ — do not edit. Regenerate with \`airframe build\`.`
- Exit codes are 0/1/2. Writes go only through the CLI's os.Root helper; `Build` outputs already do.
- Public repo: no private-project names, paths or emails.
- Reuse 3a's native plan and naming helpers; don't fork them. If one needs to change, change it once and keep the Swift goldens byte-identical.

## Decisions this plan makes

- **Options (Task 1).** Options are validated for every platform whose `emit` includes `kotlin`, whatever the platform is called. All errors are `schema-invalid`.

  | Option | Meaning |
  |---|---|
  | `package` | **Required.** A dotted Kotlin package. Each segment must be a valid identifier and not a hard keyword. |
  | `sharedOut` | Path of the shared file. Must not contain the `{<fanOut>}` placeholder. |
  | `colorSpace` | `srgb` (default) or `display-p3`. |
  | `gamut` | `css-color-4` (default) or `clip`. |
  | `material3Scheme` | A mapping from a Material 3 `ColorScheme` role to a token name. The roles are the parameters of `lightColorScheme` in material3 1.3: primary, onPrimary, primaryContainer, onPrimaryContainer, inversePrimary, secondary, onSecondary, secondaryContainer, onSecondaryContainer, tertiary, onTertiary, tertiaryContainer, onTertiaryContainer, background, onBackground, surface, onSurface, surfaceVariant, onSurfaceVariant, surfaceTint, inverseSurface, inverseOnSurface, error, onError, errorContainer, onErrorContainer, outline, outlineVariant, scrim, surfaceBright, surfaceContainer, surfaceContainerHigh, surfaceContainerHighest, surfaceContainerLow, surfaceContainerLowest, surfaceDim. |

  - Any other option key is schema-invalid.
  - A scalar `material3Scheme` (the spec's old `true`) is schema-invalid with the message `material3Scheme maps Material 3 roles to tokens, as in { primary: accent }`. This plan does not guess roles from token names.
  - Task 1 updates the spec §6.2 example to `options: { package: com.example.design, sharedOut: …, material3Scheme: { primary: accent, onPrimary: accent-contrast, primaryContainer: accent-soft } }`, and `TestSpec62ExampleLoads` keeps passing.
- **Files (Task 2).**
  - **Per-app file:** the out `kotlin` path. It may contain `{<fanOut>}`, giving one file per fan-out value.
  - **Shared file:** written to `options.sharedOut`. With no `sharedOut`, the shared declarations go at the top of the out file, which is only allowed when that path has no fan-out placeholder. Otherwise it is `emit-failed` with `platform <p>: kotlin out fans out per <axis>; set options.sharedOut for the shared DesignTokens file`.
  - **Rules for both files:**
    - Every file starts with the header, then `package <package>`, then sorted imports. Only the imports a file uses are listed.
    - The shared file must be byte-identical whichever fan-out value is built.
    - A non-colour token that varies on the fan-out axis is `emit-failed`, as in Swift: `…varies per <axis>; Kotlin non-colour tokens are shared`.
- **Names.**
  - `<Type>` is the type part of the kotlin naming template (default `DesignTokens.{camel}`). The colour types are then `<Type>Colors` and `<Type>ColorValues`, so `DesignColors` and `DesignColorValues` by default.
  - Members follow the template, so `{camel}` gives `accentInk`. Per-token `names.kotlin` overrides the template.
  - Kotlin hard keywords are wrapped in backticks: as, break, class, continue, do, else, false, for, fun, if, in, interface, is, null, object, package, return, super, this, throw, true, try, typealias, typeof, val, var, when, while.
  - A leading digit gets a `_` prefix, and any other non-identifier character is `emit-failed`.
  - A type name that is a keyword is `emit-failed`.
  - Two tokens that map to one identifier are `emit-failed`, naming both. This applies within DesignTokens and within the colour slots.
- **Colour slots.**
  - A slot is one colour token, or one shadow layer's colour, in one combination of the runtime axes other than appearance that it varies on.
  - The slot name is the member name plus `Pascal(value)` for each such axis in axis order (`surfaceCompact`), and `<member>Layer<N>` for shadow layers.
  - `<Type>Colors` is `public data class` with one `public val <slot>: Color` per slot, in sorted slot order.
- **Colour values (Task 2).**
  - `public object <Type>ColorValues` has one `public val <appearanceValue camel>: <Type>Colors` per appearance value, in axis order. With no appearance axis it has a single `public val colors`.
  - Values are resolved per (fan-out value, appearance value, slot combination) through `NativePlan.Value`.
  - With `srgb`, a colour is written `Color(0xAARRGGBB)`, with 8-bit channels and alpha rounded half up. It is gamut-mapped with `color.ToSRGB(CSSColor4)`, or with `Clip` when `gamut: clip`.
  - With `display-p3`, a colour is written `Color(red = 0.1234f, green = …f, blue = …f, alpha = …f, colorSpace = ColorSpaces.DisplayP3)`, with 4 decimals, using `ToP3` with the same gamut choice.
- **DesignTokens (Task 3).**
  - **Declaration:** `public class <Type>(public val colors: <Type>Colors, …)`. After `colors` it takes one parameter per runtime axis (appearance included) that some emitted non-colour token or colour slot needs, in axis order. Each parameter defaults to the axis's base value.
  - **Nested enums:** one `public enum class <Axis> { <Pascal values> }` per runtime axis that is a parameter.
  - **Non-colour tokens:**
    - A token that varies on nothing goes in `public companion object` as `public val`, so `DesignTokens.gap` works.
    - A token that varies is an instance `public val x: T get() = when (density) { … }`, with an exhaustive `when` and no `else`. Several axes nest, outer to inner, in axis order.
  - **Colour tokens:** instance `public val x: Color get() = colors.<slot>`, with a `when` over the non-appearance axes when there is more than one slot. Appearance never reaches here; the caller picks the `<Type>Colors` for the appearance.
  - **Types:**

    | Token type | Kotlin |
    |---|---|
    | dimension | `Dp`: `16.dp`, `1.5.dp`; px as is, rem × 16 |
    | number | `Float`: `1.5f` |
    | duration | `kotlin.time.Duration`: `150.milliseconds`, `(37.5).milliseconds` |
    | cubicBezier | `CubicBezierEasing(0.2f, 0f, 0f, 1f)` |
    | fontFamily | `List<String>` |
    | fontWeight | `FontWeight(<int>)`; a non-integer weight is rounded; outside 1..1000 is `emit-failed` |
    | shadow | `List<<Type>.Shadow>`, where `public data class Shadow(val color: Color, val x: Dp, val y: Dp, val blur: Dp, val spread: Dp, val inset: Boolean)` is nested in `<Type>`. Layer colours read the layer slots. |

- **Material 3 (Task 4).**
  - When `material3Scheme` is set, `<Type>ColorValues` also has one `public val <appearance>Scheme: ColorScheme` per appearance value. It is `lightColorScheme(…)` for `light` and `darkColorScheme(…)` for `dark`, with named role arguments in role-list order. With no appearance axis it is `lightScheme` only.
  - `emit-failed`, naming the role and the token, when:
    - an appearance value is neither light nor dark;
    - a role names an unknown or non-colour token;
    - a role's token varies on a non-appearance runtime axis (it has no single value).
- **Verification of Kotlin.**
  - Goldens, plus `TestKotlinTypechecks`. The test is skipped unless `kotlinc` is on PATH. It is on the GitHub ubuntu image; locally, `brew install kotlin`.
  - It compiles each golden together with `internal/emit/testdata/kotlin-stubs/*.kt`. These are hand-written stubs of exactly the Compose API the emitter uses, with the real packages and signatures:
    - `Color(Long)`, and `Color(red, green, blue, alpha, colorSpace)` with Float args;
    - `ColorSpaces.DisplayP3`;
    - `Dp`, and `Int.dp`, `Double.dp`;
    - `FontWeight(Int)`;
    - `CubicBezierEasing(Float, Float, Float, Float)`;
    - `ColorScheme`, and `lightColorScheme` / `darkColorScheme` with every role as a defaulted named parameter.
  - `kotlin.time` is real.
  - It also compiles the guide's ```kotlin blocks, as 3a does for Swift.
  - The final review adds one real compile: a throwaway Gradle Android library using the Compose BOM, outside the repo, built against the goldens. It is reported, not committed.
- **Registration:** `kotlin` moves from the known-future set into `emit.Emitters`. `emit-unsupported` stays for `xaml` only.

## Review Focus

1. **A colour varying on density.**
   - `surface` varying on density must give `DesignColors.surfaceCompact`/`surfaceStandard`/`surfaceRelaxed`, and `DesignTokens.surface` must switch on density.
   - The same token used as an M3 role must be `emit-failed`, not silently given its base value.
   - Tests: Tasks 2/3 `TestKotlinColorSlots`, Task 4 `TestMaterial3RoleVaries`.
2. **Identifiers.**
   - Tokens named `in`, `object` or `2xl` must give backticked or `_`-prefixed members that compile.
   - `space-4` and `space4` must be `emit-failed`, naming both.
   - Test: Task 3, `TestKotlinIdentifiers` (golden + kotlinc).
3. **An alias crossing the fan-out axis.**
   - `button-bg → {accent}`, with accent varying per app, must give each app's `DesignColorValues` its own value.
   - The shared file must be byte-identical across apps.
   - Test: Task 2, `TestKotlinFanOutThroughAlias`.
4. **Out-of-gamut OKLCH.**
   - With `srgb`, the colour must be mapped by the stated method into valid hex.
   - `clip` must clip.
   - `display-p3` must use `ColorSpaces.DisplayP3`, with components in [0,1].
   - Test: Task 2, `TestKotlinGamut`.
5. **`sharedOut` absent while the kotlin out fans out** must be `emit-failed` with the message above. With no fan-out, one file must hold both parts and compile. Test: Task 2, `TestKotlinSharedOut`.

Determinism (two builds, shuffled read order, byte-identical) is Task 5, `TestAndroidDeterministic`.
