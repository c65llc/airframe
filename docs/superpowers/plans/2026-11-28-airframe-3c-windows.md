# Airframe 3c · Windows emitter (WinUI 3 XAML ResourceDictionary) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `airframe build` emits, for a platform with `emit: [xaml]`, one WinUI 3 `ResourceDictionary` per fanned-out app. Colours are theme-aware brushes (Light, Dark, and HighContrast or Default), and every other token is a typed resource. `build --check` and `emitted-stale` cover the dictionaries like every other output.

**Architecture:** The `xaml` emitter sits on 3a's native plan (`internal/emit/native.go`) and naming helpers (`naming.go`). Appearance becomes `ThemeDictionaries`. Every other runtime axis becomes one suffixed resource per value. The build-bound fan-out axis gives one file per value. Everything else follows `internal/emit/kotlin.go` and `swift.go`: identifier rules, collisions, header, goldens, and `requireDeterministic`.

**Model:** the 3a and 3b emitters, and the conventions of an existing WinUI 3 app's token dictionary:
- `<ResourceDictionary.ThemeDictionaries>` with `x:Key="Light"`, `"Dark"` and `"HighContrast"`;
- colours as `<SolidColorBrush x:Key="…" Color="#AARRGGBB" />`;
- high-contrast brushes as `Color="{ThemeResource SystemColorHighlightColor}"`;
- dimensions as `<x:Double>`;
- `<FontFamily>` and `<CornerRadius>` resources.

**Tech Stack:** Go 1.27 (`toolchain go1.27.4`), pinned deps only, `encoding/xml` for the structural check. The output targets WinUI 3 (Windows App SDK 1.8).

**Spec:** `docs/specs/2026-11-27-airframe-design.md` §6.2 (the `windows` platform, `naming.xaml: "Design{Pascal}"`, `options.gamut: clip-srgb`) and §6.7 item 3.

## Global Constraints

- **License header** on every Go file: `// SPDX-License-Identifier: AGPL-3.0-only`, then `// Copyright 2026 C65 LLC`.
- **Deterministic, byte-stable output:** LF line endings, a final newline, no timestamps. Never range a map without sorting its keys. `requireDeterministic` (in `internal/emit/emit_test.go`) must pass.
- **Fail closed:** anything WinUI cannot express is a diagnostic that names it. Never drop it silently and never guess.
- **Header:** an XML comment as the first child of the root: `<!-- GENERATED by airframe from <content>/ — do not edit. Regenerate with `airframe build`. -->`
- **Exit codes** are 0, 1 or 2. Writes go only through the CLI's os.Root helper.
- **Public repo:** no private-project names, paths or emails.
- **Reuse 3a and 3b helpers.** Keep the Swift and Kotlin goldens byte-identical.

## Decisions this plan makes

### Options (Task 1)

Options are validated for every platform whose `emit` includes `xaml`. Errors are `schema-invalid`, and every value must be a YAML string.

- **`gamut`:** `css-color-4` (default) or `clip-srgb`. XAML colours are sRGB `#AARRGGBB`. With `css-color-4` the colour is gamut-mapped with `color.ToSRGB(CSSColor4)`; with `clip-srgb` it uses `Clip`.
- **`highContrast`:** a mapping from a colour or shadow token name to one of the WinUI high-contrast system colours: `SystemColorWindowTextColor`, `SystemColorWindowColor`, `SystemColorHighlightColor`, `SystemColorHighlightTextColor`, `SystemColorHotlightColor`, `SystemColorGrayTextColor`, `SystemColorButtonFaceColor`, `SystemColorButtonTextColor`. An empty mapping, an unknown system colour, or a non-string value is schema-invalid. Export the list as `config.SystemColors`.
- **Any other key** is schema-invalid.
- **Accessor:** `func (p Platform) HighContrast() [][2]string`, returning (token, system colour) pairs sorted by token.

### File (Task 2)

- **Path:** one file per fan-out value at the `xaml` out path, with `{<fanOut>}` replaced. If the out path has no fan-out placeholder, there is one file. In that case a token that varies per fan-out value is `emit-failed` with `token "x" varies per <axis>; put {<axis>} in the xaml out path`.
- **Root element:** `<ResourceDictionary xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation" xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml">`.
- **Body order:**
  1. the header comment;
  2. `<ResourceDictionary.ThemeDictionaries>`, only when there are colour resources;
  3. the non-colour resources, sorted by key.
- **Formatting:** 4-space indent. Attribute and text values are XML-escaped.

### Keys

- **Naming:** a resource key comes from the `xaml` naming template (default `Design{Pascal}`). Per-token `names.xaml` overrides it. The template has no type part.
- **Validity:** a key must match `^[A-Za-z_][A-Za-z0-9_]*$`. A key that doesn't is `emit-failed` naming the token. There is no backtick escape in XAML.
- **Runtime axes other than appearance:** a token that varies on one gets one resource per combination of those axes. The key is the key plus `Pascal(value)` per axis, in axis order, for example `DesignGapCompact`. It also gets the plain key, holding the base combination, so `{StaticResource DesignGap}` always resolves.
- **Collisions:** two resources with one key in the same dictionary are `emit-failed`, naming both tokens.

### Colours

Every emitted colour token, and each shadow layer's colour (`<Key>Layer<N>`), is a `SolidColorBrush`.

- **Light and Dark dictionaries:** `ThemeDictionaries` holds `x:Key="Light"` and `x:Key="Dark"`. The `light` appearance value fills Light and `dark` fills Dark.
  - With no appearance axis, Light and Dark carry the same values.
  - An appearance axis with any other value is `emit-failed`.
- **HighContrast:**
  - If `highContrast` is set, a `x:Key="HighContrast"` dictionary maps every colour brush to `Color="{ThemeResource <SystemColor>}"`. Every colour token and every shadow token (one mapping covers all its layers) must be mapped. Otherwise it is `emit-failed`, listing the unmapped tokens.
  - A mapped token that isn't an emitted xaml colour or shadow token is `emit-failed`.
  - If `highContrast` is absent, `x:Key="Default"` repeats the base appearance values, so a high-contrast theme still resolves every key. The guide says to set `highContrast` for accessible high-contrast support.
- **Brush shape:** `<SolidColorBrush x:Key="DesignInk" Color="#FF12171B" />`. Values are 8-bit, rounded half up.

### Non-colours

These sit at the dictionary's root, after the theme dictionaries. A non-colour token that varies on appearance (a shadow's geometry included) is the exception: it is written into every theme dictionary beside the brushes, Light and Dark at their values and HighContrast or Default at the base appearance's, and consumers read it with `{ThemeResource}`. WinUI theme dictionaries hold any resource. *(Ruling at Task 2 review, amending this plan: emit-failing every design system with an appearance-varying dimension was too blunt.)*

| Token type | XAML resource |
|---|---|
| dimension | `<x:Double>` in effective pixels: px as is, rem × 16 |
| number | `<x:Double>` |
| duration | `<x:Double>` in milliseconds, key unchanged (the guide documents the unit) |
| cubicBezier | `<KeySpline x:Key="…" ControlPoint1="x1,y1" ControlPoint2="x2,y2" />` |
| fontFamily | `<FontFamily>` with the families joined by `, ` |
| fontWeight | `<x:Double>`, the numeric weight (the guide documents converting it with `new FontWeight((ushort)w)`) |
| shadow | per layer: `<Key>Layer<N>OffsetX`, `…OffsetY`, `…Blur`, `…Spread` as `x:Double`, and the colour brush above. An inset layer is `emit-failed`, because WinUI has no inset shadow. |

`x:Double` text uses the shortest decimal, the same formatting the other emitters use for numbers.

### Verification

- **Goldens.**
- **`TestXAMLWellFormed`** checks each golden with `encoding/xml`. The root and namespaces must be correct, and no dictionary may hold two equal `x:Key`s. Every brush key in Light, and every themed non-colour key, must also appear in Dark and in HighContrast or Default, and nowhere else. Non-colour elements must be one of `x:Double`, `KeySpline` or `FontFamily`.
- **No WinUI compile.** That would need a Windows host with the Windows App SDK. Final review attempts one only if a Windows machine is reachable; otherwise the guide and the PR say the output is structurally checked, not compiled.

### Registration (Task 3)

- `xaml` joins `emit.Emitters`.
- With every accepted format built, `emit-unsupported` can no longer fire. It leaves `lint.AllIDs` and the self-test, along with the `flag/emit-unsupported` fixture and `lint_emit_formats.txtar`'s expectation. Its docs page stays, because IDs are addresses: it gets front matter `retired: v0.5.0` and a sentence saying no format triggers it any more. `docs_test` accepts a page for a retired ID.
- `Build`'s "no emitter for format" path becomes an internal error (exit 2) rather than a diagnostic, because config only accepts built formats.

## Review Focus

1. **Missing HighContrast mappings.** A colour token with no `highContrast` mapping while others are mapped must be `emit-failed`, naming every unmapped token. It must not produce a HighContrast dictionary with missing keys, which crashes at runtime in high-contrast mode. → Task 2, `TestXAMLHighContrastIncomplete`.
2. **Tokens varying on density.** `gap` varying on density must give `DesignGapCompact`, `DesignGapStandard` and `DesignGapRelaxed`, plus a plain `DesignGap` with the base value. A colour that varies on density must give suffixed brushes in every theme dictionary. → Task 2, `TestXAMLRuntimeSuffix`.
3. **Keys that aren't XAML identifiers.** `names.xaml: "my-ink"` or a template giving `Design2xl`-style keys must be valid or `emit-failed`. Two tokens giving `DesignSpace4` must be `emit-failed`, naming both. → Task 2, `TestXAMLKeys`.
4. **Out-of-gamut OKLCH.** It must be mapped by CSS Color 4 into valid `#AARRGGBB`, and `clip-srgb` must clip. → Task 2, `TestXAMLGamut`.
5. **Retiring `emit-unsupported`.** The self-test, `airframe rules` and the docs must all agree. No test or fixture may still expect it, and a config using every format must build. → Task 3, the self-test, `TestRulesList` and `docs_test`.
